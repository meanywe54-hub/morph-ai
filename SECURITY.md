# Security

The offline demo does not execute generated code. The Docker synthesis runtime executes model output inside a container, but Docker shares the host kernel and the implementation has not yet been verified with a live Docker daemon. It is not a hardened multi-tenant sandbox. Use only a trusted daemon and image on a disposable isolated host; container cleanup after daemon failure is best effort. Never mount credentials or a Docker socket into the container. Please report security issues privately to the repository maintainers through GitHub's private vulnerability reporting if enabled; avoid publishing exploit details before a fix is available.

The optional `bounded-integer-v1` runtime interprets a restricted, bounded integer language without executing Python. It has no I/O primitives, accepts a fixed AST subset, and rejects unknown syntax before interpretation. It is not a sandbox for general Python. Its trusted interpreter needs security review; report any construct that escapes its language or resource limits as a security issue. The runtime contract is documented in `docs/bounded-runtime.md`.

The `repair` command uses the same interpreter for an undecorated function with positional integer arguments. It disallows calls and loops, never imports the target module, and exports a diff for review. It sends only the selected function, optional description and failed development examples to the installed model on the loopback interface. Review the diff and use trusted tests to verify behavior in the real project. [Repair scope](docs/python-repair.md)
